Who does what

Two roles, two experiences

muhfarming has exactly two roles. Everyone can read the shared data; what you can write depends on your role. The app and API enforce this for you.

Farmer default

  • Self-register in seconds (signup always creates a Farmer)
  • Create & manage their own farms
  • Add & edit fields, coordinates and crops
  • Read all broadcast alerts
  • Cannot create or edit alerts
  • Cannot manage reference data or other users

Admin privileged

  • Everything a Farmer can do — across all data, not just their own
  • Create & broadcast alerts to every user
  • Manage reference data (regions, incidents, hazards, cultivations…)
  • Create and manage user accounts
  • Admins are created by another admin — never via public signup
Reads for farmers are scoped to their own data (their farms, their fields). Admins see everything. Alerts are the exception — they're broadcast, so every authenticated user reads them.
Step 1

Register & sign in

Public signup creates a Farmer account and returns a JWT token. Send that token as Authorization: Bearer <token> on every request after this.

Create a Farmer account Farmer

Username and password only. Password must be at least 6 characters.

POST http://localhost:8080/auth/signup
# Content-Type: application/json
{
  "username": "jane",
  "password": "secret6"
}

# → 201 Created
{
  "token": "<jwt>",
  "role": "Farmer"
}

Log in later

Same body, same response. Tokens are valid for 24 hours.

POST http://localhost:8080/auth/login
{
  "username": "jane",
  "password": "secret6"
}
# → 200 { "token": "...", "role": "Farmer" }

Need an Admin? Admin

Admins can't be created through signup. An existing admin provisions them via the user-management endpoint.

POST http://localhost:8080/users  # admin token required
{
  "username": "boss",
  "password": "secret6",
  "name": "Alex",
  "email": "alex@farm.io",
  "role": "Admin"
}
Only Admin and Farmer are valid roles. Anything else is rejected by validation.
Step 2

Create a farm

Any signed-in user can create a farm — it's automatically owned by you. All you need is a name.

Add your farm Farmer Admin

POST http://localhost:8080/farms  # Bearer token
{
  "name": "North Farm"
}

# → 201 { "id": 1, "name": "North Farm", "userId": 7, ... }
userId is set from your token — you don't send it. Farmers see only their own farms when they GET /farms; admins see every farm.

List your farms

GET http://localhost:8080/farms       # your farms (admin: all)
GET http://localhost:8080/farms/1     # one farm
Step 3

Add fields to a farm

Fields belong to a farm and sit in a region. Farmers can now add their own fields directly — no admin needed.

Region reference data

Create a field Farmer Admin

You'll need the farmId from step 2 and a regionId. List regions with GET /regions.

POST http://localhost:8080/fields  # Bearer token
{
  "name": "Plot A",
  "fieldNotes": "clay soil, west slope",
  "farmId": 1,
  "regionId": 3
}

# → 201 Created (field with nested farm + region)
Regions are reference data: everyone can read them, but only admins can create them. Pick an existing regionId.
Step 4

Send & retrieve alerts

An alert links a field to an incident (the hazard) and is broadcast to everyone. Admins send them; all users read them.

Broadcast an alert Admin only

Reference an existing field and an incident. The incident carries the hazard details.

POST http://localhost:8080/alerts  # admin token required
{
  "fieldId": 5,
  "incidentId": 2
}

# → 201 Created
# A Farmer who POSTs here gets 403 "admin privileges required"

Retrieve alerts Farmer Admin

Every authenticated user sees all alerts — regardless of who owns the field. Each alert comes with its field and incident preloaded.

GET http://localhost:8080/alerts       # all alerts, broadcast
GET http://localhost:8080/alerts/1     # one alert + field + incident
Because alerts are broadcast, a farmer sees hazard alerts even for fields they don't own — so the whole community stays informed.
